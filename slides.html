Key Concepts

MCP is a standard interface between AI models and services

Without MCP, every integration requires custom code. MCP gives every service the same interface, so any AI model can discover and call tools from any server, regardless of what language either side is written in.

MCP Servers

Each server is a standalone process that exposes tools

  • Defines tools with names, descriptions, and parameter schemas
  • Communicates over stdio (local) or Streamable HTTP (production)
  • Returns structured JSON, success or a recoverable error
  • Runs independently, a crash in one server does not affect the others

Our 5 servers

ticket · customer · billing · knowledge base · asset
20 tools total, all discoverable by the AI model at runtime

# Every server follows the same pattern
from mcp.server import Server
from mcp.types import Tool

app = Server("ticket-management-server")

@app.list_tools()
async def list_tools():
    return [
        Tool(
            name="search_tickets",
            description="Search tickets by
            priority, status or customer",
            inputSchema={
                "type": "object",
                "properties": {
                    "priority": {"type": "string"},
                    "status":   {"type": "string"}
                }
            }
        )
    ]

@app.call_tool()
async def call_tool(name, arguments):
    if name == "search_tickets":
        return search_tickets(**arguments)

Error Design

Errors are written for the AI model, not for humans

When a tool fails, the server does not just say "not found." It explains what went wrong, whether the call can be retried, and which tool to try next. This lets the model recover on its own without asking the user.

Example: find_related_articles("KB-999")

Article KB-999 does not exist. The server cannot suggest related content, but it tells the model exactly what to do instead.

{
  "error":
    "Article KB-999 not found",

  "reason":
    "Cannot recommend related content
    because the source article
    does not exist.",

  "suggested_actions": [
    "Run search_solutions using the
    article topic to find entries.",
    "Confirm the article_id format
    (e.g., KB-001)."
  ],

  "retryable":      true,
  "follow_up_tools": ["search_solutions"]
}

Orchestration

The orchestrator connects the model to all servers

User "Critical tickets for CUST-001?"
Orchestrator → gpt-5-nano question + 20 tool definitions
gpt-5-nano decides search_tickets(customer_id="CUST-001", priority="critical")
Orchestrator → ticket_server routes call, returns results
Final answer "CUST-001 has 2 critical tickets…"

MCPOrchestrator in mcp_client.py is custom code built on top of the MCP SDK. The SDK provides the low-level primitives. The orchestrator adds the coordination layer.

  • Starts all 5 servers as subprocesses
  • Collects all 20 tool definitions at startup
  • Converts MCP schemas to OpenAI function format
  • Loops until the model produces a final answer
